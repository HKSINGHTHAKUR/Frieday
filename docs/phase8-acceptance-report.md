## 10. Disconnect/reconnect investigation findings

### Root cause: expected GitHub SSO behavior, not a Frieday defect

**Observed behavior** (owner report):

1. Settings → click "Disconnect GitHub" → redirected to `/login` ✅
2. Login page → click "Connect with GitHub" → returns directly to dashboard without seeing GitHub's consent screen
3. Owner suspected the connection/token may not have been fully cleared

### Implementation inspection

**`POST /api/auth/disconnect`** (`server/src/routes/auth.routes.js:303-354`) — fully correct:

1. Revokes GitHub grant via `revokeGrant()` (`services/github/revoke.js:14-32`) — best-effort, failures silently logged
2. Clears `githubTokenEnc`, `sessionId`, `refreshTokenHash` on the User document (`auth.routes.js:335-338`)
3. Clears `fd_access` + `fd_refresh` cookies (`auth.routes.js:352`)
4. Returns 204

**Client-side `AuthStore.disconnect`** (`client/src/store/AuthStore.jsx:107-115`):

1. Calls `apiPost('/api/auth/disconnect')`
2. `markSessionLost()` — clears React context state
3. `navigate('/login', { replace: true })` — full-page redirect to login

**Re-auth flow** (`Login.jsx:62-73` → `auth.routes.js:56-69`):

- "Connect with GitHub" → `window.location.replace('/api/auth/github')` → sets fresh `fd_oauth_state` cookie → redirects to GitHub
- OAuth callback (`auth.routes.js:79-162`) validates state, exchanges code, issues fresh session cookies, redirects to `/dashboard?connected=1`

### Why GitHub skips the consent screen on re-auth

This is **standard GitHub OAuth SSO behavior**, not a Frieday defect:

1. Disconnect clears Frieday's stored token and session — **confirmed working** (unit test passes: `user-endpoints.test.js:318-343`)
2. `revokeGrant()` is **best-effort** — if GitHub's revocation endpoint is unreachable or the token can't be decrypted, the failure is silently swallowed (`auth.routes.js:324-331`)
3. GitHub **remembers the OAuth grant** once authorized. Re-authorizing the same app skips consent and returns a code immediately
4. Frieday exchanges the code, issues a fresh session — the user's Frieday session IS fully cleared

This is identical to Google, GitHub, and other OAuth providers. Re-authorizing an already-approved app skips consent.
